# ASIC PPA：硬體版本比較

PPA 是晶片設計最常用的三個指標：面積（Area）、效能（Performance）、功耗（Power）。本頁比較同一顆 CPU 的兩個完整實作版本：

- **H0**：原本的實作。
- **H1**：縮小晶片的版本。

兩版使用同一份邏輯網表、同一套製程與工具、同樣的時脈與工作負載，也都通過同一套 DRC、LVS、antenna、STA、功能檢查，以及 dummy metal fill／密度、靜態 IR／平均 EM、網路連通等實體檢查，所以兩版之間的差異只來自實體實作。

## **1．比較的兩個版本**

| **項目** | **H0** | **H1** |
| --- | --- | --- |
| 邏輯網表 | 合成後的 `mapped_top.v` | 同一份 |
| SRAM | 18 顆 2 KiB（共 36 KiB），3 欄 × 6 列 | 相同排列與方向，外緣同為 120 µm |
| SRAM 間隔（欄／列） | 96.9／103.5 µm | 89.9／95.5 µm |
| Die | 2500 × 3300 µm（8.250 mm²） | 2470 × 3217 µm（7.946 mm²） |
| Placement／CTS／Routing 設定 | 原始設定 | 從 H0 複製，只改 floorplan |
| 時序約束 | 審查後的 SDC | 同一份 |

### **為什麼選「縮小晶片」當 H1**

在決定 H1 之前，先掃描了合成策略：

- H0 已經使用以面積為主的合成設定。
- 最好的替代設定只少 0.94% 的邏輯面積，換算成 die 只少約 0.03%。
- 以速度為主的設定會多 13–18% 面積，繞線前的 setup 也沒有明顯改善。

合成策略不是有意義的改變方向。晶片面積大部分是 SRAM，所以改成縮小 SRAM 之間的通道。

### **縮小幅度的選擇**

只縮小 SRAM 之間的間隔，選「global routing 沒有溢位」中 die 最小的一組：

| **方案** | **欄／列間隔（µm）** | **Die（mm²）** | **相對 H0** | **Global routing** |
| --- | --- | --- | --- | --- |
| H0 | 96.9／103.5 | 8.250 | — | 無溢位 |
| gap80 | 80.9／80.5 | 7.704 | −6.6% | 溢位 6,047，不可繞線 |
| gap85x88 | 84.9／88.5 | 7.828 | −5.1% | 溢位 7,637，不可繞線 |
| gap88x92 | 87.9／92.5 | 7.896 | −4.3% | 溢位 1,914，不可繞線 |
| **gap90x95（H1）** | 89.9／95.5 | 7.946 | **−3.7%** | 無溢位，資源使用率 28.8% |
- 以 gap80 為例，約 86% 的溢位落在 SRAM 上方容量為 0 的區域：通道裝不下的走線被擠到 SRAM 邊緣。
- 間隔再縮小到 70 或 60 µm 時，可放置區的元件密度會到 65% 或 87%，判斷不可行。

## **2．比較方法**

| **項目** | **設計** |
| --- | --- |
| 製程／元件庫 | SKY130A、sky130_fd_sc_hd；固定版本的開源工具 |
| PVT／RC | TT 25°C／1.8V；時序列出 min／nom／max 三種導線 RC，功耗使用 nom RC |
| 時脈 | 25 MHz（40 ns） |
| 面積 | 從最終版圖統計 die、core、SRAM、標準元件（再分成邏輯、tap、antenna diode）與 filler |
| 效能 | STA 的最差 setup slack；以「40 ns − slack」換算最高頻率的推估值；工作負載的週期數 |
| 切換活動 | 在各自的最終網表上執行 4 個工作負載並產生 VCD，對應到每條 routed net |
| 功耗 | OpenSTA 讀 VCD 與 nom SPEF，分成 Sequential、Combinational、Clock、SRAM 四群 |
| 能量 | 平均功耗 × 量測時窗；時窗從初始化完成到程式結束，不含 reset 和載入程式 |

| **工作負載** | **內容** | **週期** |
| --- | --- | --- |
| idle | 待機 | 256 |
| mixed | 自訂指令、DMA、DOT4 加速器的功能測試 | 1,159 |
| dot64_rv32i | 64 次乘加，只用 RV32I 指令 | 21,708 |
| dot64_custom | 同樣的 64 次乘加，用自訂指令 | 1,022 |

```
各版本最終版圖
      │
      ├── 面積統計
      ├── 三種 RC 萃取 → STA → setup／hold slack
      │
      ▼
最終網表上的功能模擬（4 個工作負載）
      │  產生 VCD，對應每條 routed net
      ▼
OpenSTA 功耗分析（nom RC）
      │
      ▼
自動檢查一致性 → H0／H1 比較表
```

彙整時會自動檢查，任何一項不符就不產生結果：

- 沒有未標註活動的 pin；
- 18 顆 SRAM 的功耗加總等於 Macro 群組；
- 時窗長度等於「週期數 × 40 ns」；
- 功能模擬、活動與功耗都使用同一份網表和版圖。

| Tap＋antenna diode | 43,358 | 32,140 | −25.9% |
| Filler | 905,807 | 629,077 | −30.6% |

| **TT RC 條件** | **Setup slack H0 → H1** | **Hold slack H0 → H1** | **推估最高頻率 H0 → H1** |

| **指標** | **H0** | **H1** |
| --- | --- | --- |
| 週期 rv32i ÷ custom | 21.24× | 21.24× |

## **4．結果解讀**

| **觀察** | **說明** |
| --- | --- |
| SRAM 決定大部分 PPA | SRAM 佔 die 的 62–64%、佔總功耗 74–78%，兩版完全相同，所以整體差距不大 |
| 縮小的效果被放大到邏輯區 | die 只少 3.7%，但 SRAM 不變，可放置標準元件的面積少了 13.1%；tap 與 filler 跟著減少，邏輯本身幾乎不變 |
| Setup 改善不是縮小造成的 | H0 最差路徑的邏輯被擺在一顆 SRAM 的上下兩側，訊號來回跨越，39 個長線 buffer 佔 13.75 ns。H1 重新擺放後，同一批元件比較集中。SRAM 間隔只縮了 7–8 µm，這個差異來自擺放結果，換一次擺放可能就不同 |
| 時脈功耗固定增加 | 時脈沒有 gating，每個週期都在翻轉。H1 的時脈樹是重新產生的：buffer 多 20 顆，主幹 buffer 也加大過，所以每個工作負載都多 0.20 mW |
| 組合邏輯功耗略增 | H1 總線長反而少 1%，差異來自個別高活動網路的位置；對總功耗的影響約 0.3% |
| 能量差 = 功耗差 | 兩版週期數相同，能量比例與功耗比例一致 |

**取捨**：以面積為主要指標時，H1 較好（−3.7%）；功耗多不到 1%。兩版在 25 MHz 下的 setup 餘裕都至少有 5.7 ns，推估最高頻率都在 29 MHz 以上。代價是通道變窄後比較難繞線。

## **5．實作要點**

縮小晶片後重新實作，有幾個步驟決定了能不能收斂：

| **項目** | **做法** |
| --- | --- |
| 繞線前修復不能省 | Global route 之後、detailed route 之前，要做長線分段與時序修復：長線門檻 500 µm、slew／cap 留 30% 餘裕、hold 留 0.3 ns 餘裕。少了這一步，修復用的 buffer 只有幾百顆，而不是約一萬顆；繞線後會出現大量 slew／cap 違規，打進 SRAM 的路徑也會有 hold 違規 |
| Antenna diode 要早插 | 在 global route 階段就處理 antenna。若在 detailed route 之後才插入數千顆 diode，會把已經乾淨的繞線打亂，造成很長的 DRC 迴圈 |
| SRAM 角落壅塞 | 通道變窄後，繞線違規集中在 SRAM 角落；做法是清掉角落小窗口內的網路，再限次數重繞 |
| 時脈主幹 | 一般 global route 不會讓時脈線維持在上層金屬，所以另外做一次「只有時脈」的 global route，限定走 met3／met4。Repeater 的位置對 hold 影響很大，最後選擇在主幹 driver 旁加一顆 |
| 補 diode 後要重查 | 補天線時會重繞部分網路。這次有 7 條網路因此 slew／cap 超限，加大 driver 後才通過 |
| 繞線後修補規則 | 依實際 RC 找出違規網路，選最小但足夠的驅動尺寸並留 15% 餘裕；自動規劃時，時脈網路只加大驅動、不插 buffer，時脈分支另外個別處理 |
| 電源 via 要跟著加強 | SRAM 供電路徑上原本只有單切孔的 via4，平均電流超過 EM 限值。改成 8 切孔或更大的陣列，電流最集中的地方再加寬 M4。電源 via 只動電源線，附近少數訊號線的耦合電容只有極小變化，PPA 數字不受影響。縮小後 EM 餘裕比 H0 小（28 mW 時最大利用率 0.98 對 0.88） |
| 檢查腳本要跟著 die 尺寸 | 密度檢查的視窗範圍必須用實際 die 邊界；沿用舊版本的尺寸，會把 die 外的空白算進邊緣視窗，造成假的密度不足 |

## **6．限制**

| **項目** | **影響** |
| --- | --- |
| SRAM 功耗模型 | 解析模型，有沒有存取功耗都一樣，每顆固定 1.3986 mW。兩版相同，比較時會抵消，但總功耗的絕對值主要取決於這個未經驗證的模型 |
| 擺放變異 | 每版只有一次擺放，時序差異不能當作縮小的效果 |
| 未知值 | 約 5.3–5.5% 的網路時間是未知值，來自沒有被讀取的 SRAM bank 輸出 |
| 零延遲模擬 | 沒有 SDF，glitch 功耗沒有算進去 |
| PVT | 只有 TT 25°C／1.8V |
| IR／EM | 兩版都只做靜態、平均電流篩檢，沒有暫態、封裝與 SRAM 內部分析 |
| 製造 | 兩版都沒有 SRAM 多 PVT 模型、fill-aware PEX 與 foundry 簽核，不能直接投片；沒有晶片量測 |

功耗分析流程可對照 [OpenSTA 文件](https://github.com/The-OpenROAD-Project/OpenSTA)。
