# 大致架構

**1．整體執行原則**

- 採多周期架構，一次執行一條指令。
- 指令執行期間 PC 保持不變，正常完成時才更新。
- 暫存器在 clock 上升緣更新；等待時可保持原值。
- Execute 保存結果，後續 Writeback／Commit 再使用。
- 指令與資料介面分離，全核心最多一筆未完成交易。
- 錯誤時停止，保存原因與位址，不進行該錯誤指令的正常提交。
- 未啟用的寫入使能預設為 0；組合邏輯選擇訊號仍須有明確預設值。

---

**2．內部暫存器與停止狀態**

| 暫存器 | 寬度 | 保存內容 | 何時更新 |
| --- | --- | --- | --- |
| **PC** | 32-bit | 取指所用位址；目前指令執行期間保持不變 | Reset、指令正常完成時 |
| **IR** | 32-bit | 目前執行的機器指令 | 取指成功時 |
| **InstrPC** | 32-bit | IR 這條指令所在的位址 | 與 IR 同時更新 |
| **A** | 32-bit | rs1 的資料 | Decode 結束時 |
| **B** | 32-bit | rs2 的資料 | Decode 結束時 |
| **ALUOut** | 32-bit | 運算結果、Load／Store 有效位址或跳躍目標 | 對應 Execute 階段結束時 |
| **MDR** | 32-bit | Load 讀回的原始 32-bit 資料 | 資料讀取成功時 |
| **BranchTaken** | 1-bit | 分支條件是否成立 | BR_EXEC 結束時 |
| **State** | 依狀態編碼決定 | FSM 目前狀態 | 每個上升緣載入 next_state；等待時可保持原狀態 |
| **mem_pending** | 1-bit | 已有請求被接受，正在等待回應 | 請求接受時設 1；回應接受或 Reset 時清 0 |
| **halt_cause** | 4-bit | 停止原因 | 首次進入 HALTED 時；Reset 時清除 |
| **fault_pc** | 32-bit | 發生事件的指令位址 | 首次進入 HALTED 時；Reset 時清除 |
| **fault_addr** | 32-bit | 相關存取／跳躍位址，無相關地址時為 0 | 首次進入 HALTED 時；Reset 時清除 |

`halted` 由 `State == HALTED` 產生，不需要另外增加一個保存相同資訊的暫存器。

**3．Datapath**

```
PC ──→ 指令記憶體介面 ──→ IR
│                         ├──→ Decoder ──→ 控制器 FSM
│                         ├──→ rs1／rs2／rd 編號
└──→ InstrPC              └──→ Immediate Generator ──→ Imm

rs1／rs2 編號
      │
      ▼
 Register File
   │        │
   ▼        ▼
   A        B ──→ Store 資料對齊邏輯 ──→ 寫入資料、byte enable

A／InstrPC／0                     B／Imm
      │                            │
      ▼                            ▼
ALU 左輸入 MUX                ALU 右輸入 MUX
      │                            │
      └─────────────┬──────────────┘
                    ▼
                   ALU
                    │
                    ▼
            JALR 目標處理
         （僅 JALR 清除 bit 0）
                    │
                    ▼
                 ALUOut
                    │
        ┌───────────┼─────────────────┐
        ▼           ▼                 ▼
 資料記憶體介面  Writeback MUX       PC MUX
        │           ▲                 ▲
        ▼           │                 │
       MDR          │            InstrPC＋4
        │           │
        ▼           │
 Load 擷取／擴展 ───┤
                    │
       InstrPC＋4 ──┘

 Writeback MUX ──→ Register File 的 rd
 PC MUX        ──→ PC

A、B ──→ Branch Comparator ──→ BranchTaken
                                   │
                                   ▼
                              控制器 FSM
                                   │
                            控制 PC MUX／pc_we
```

Store 對齊與 Load 擷取使用 **ALUOut 的低位地址**及指令指定的存取寬度。

| 元件 | 功能 |
| --- | --- |
| Immediate Generator | 從 IR 重組、擴展立即數 |
| ALU 輸入 MUX | 選擇 A／InstrPC／0 與 B／Imm |
| ALU | 算術、邏輯、比較、移位及地址計算 |
| JALR 目標處理 | 僅在 JALR 時清除 ALU 結果 bit 0 |
| Branch Comparator | 比較 A、B，支援相等與 signed／unsigned 大小比較 |
| Store 資料對齊邏輯 | 準備寫入資料及 byte enable |
| Load 擷取／擴展邏輯 | 擷取 byte／halfword／word，進行符號或零擴展 |
| Writeback MUX | 選 ALUOut／Load 結果／InstrPC＋4 |
| PC MUX | 選 InstrPC＋4／ALUOut |
| 對齊檢查邏輯 | 檢查資料存取地址及實際採用的跳躍目標 |

主要 ALU 之外，保留 **InstrPC＋4 加法電路**及 **Branch Comparator**。

---

**4．ALU 輸入與結果用途**

| 指令用途 | ALU 左輸入 | ALU 右輸入 | 運算／結果用途 |
| --- | --- | --- | --- |
| ADD／SUB／AND 等 | A | B | 指定運算，結果存入 ALUOut |
| ADDI／ANDI 等 | A | Imm | 指定運算，結果存入 ALUOut |
| Load／Store | A | Imm | 相加得到有效位址 |
| Branch／JAL | InstrPC | Imm | 相加得到跳躍目標 |
| JALR | A | Imm | 相加並清除 bit 0，再存入 ALUOut |
| AUIPC | InstrPC | U-type Imm | 相加，結果供寫回 |
| LUI | 0 | U-type Imm | 相加，結果供寫回 |

---

**5．PC 更新規則**

> 執行一條指令期間 PC 保持不變；該指令正常完成時，再更新成下一個位址。
> 

| 情況 | PC 行為 |
| --- | --- |
| 一般運算、Load、Store | PC←InstrPC＋4 |
| FENCE 正常完成 | PC←InstrPC＋4 |
| Branch 不成立 | PC←InstrPC＋4 |
| Branch 成立且目標對齊 | PC←分支目標 |
| JAL／JALR 目標對齊 | PC←跳躍目標 |
| 記憶體還沒回應 | 保持不變 |
| 錯誤、ECALL／EBREAK 停止 | 保持不變，記錄原因 |

**6．代表指令執行流程**

| 指令 | Decode | Execute | 後續動作 | 下一個 PC |
| --- | --- | --- | --- | --- |
| `sw x6,8(x5)` | A←x5；B←x6；Imm＝8 | ALUOut←A＋Imm | 確認資料地址對齊後發出寫入，等待成功；不寫回 rd | InstrPC＋4 |
| `lw x7,8(x5)` | A←x5；Imm＝8 | ALUOut←A＋Imm | 確認對齊後讀取；成功時保存 MDR，再將 Load 結果寫回 x7 | InstrPC＋4 |
| `beq x5,x6,target` | A←x5；B←x6；Imm＝偏移 | ALUOut←InstrPC＋Imm；BranchTaken←比較結果 | BR_COMMIT 根據 BranchTaken 選擇 PC；僅成立時檢查目標對齊 | 成立：ALUOut；否則：InstrPC＋4 |
| `jal x1,target` | Imm＝偏移 | ALUOut←InstrPC＋Imm | JUMP_COMMIT 確認對齊後，x1←InstrPC＋4，並更新 PC | ALUOut |
| `jalr x1,12(x5)` | A←x5；Imm＝12 | ALUOut←`(A＋Imm) & 0xFFFFFFFE` | JUMP_COMMIT 確認對齊後，x1←InstrPC＋4，並更新 PC | ALUOut |
- **Execute 與 Commit 分開**，避免在保存 ALUOut 的同一個邊緣誤用其舊值。
- Jump Commit 檢查的是**目標對齊**；目標指令能否成功讀取，由下一次 Fetch 判定。
- 記憶體交易失敗時進入錯誤路徑，不進行正常寫回或 PC 前進。

**7．FSM 狀態表**

| 狀態 | 這個狀態做什麼 | 成功後去哪裡 |
| --- | --- | --- |
| **FETCH** | 發出一次取指交易，等待回應；成功時保存 IR、InstrPC | DECODE |
| **DECODE** | 辨認指令、檢查是否合法、保存 A／B | 依指令類別分流 |
| **ALU_EXEC** | 執行算術、邏輯、移位、比較、LUI／AUIPC；保存 ALUOut | ALU_WB |
| **ALU_WB** | ALUOut 寫回 rd，PC←InstrPC＋4 | FETCH |
| **ADDR_EXEC** | 計算 Load／Store 的有效位址，保存 ALUOut | MEM_CHECK |
| **MEM_CHECK** | 檢查資料地址是否符合存取寬度的對齊要求 | LOAD_WAIT 或 STORE_WAIT |
| **LOAD_WAIT** | 發出一次讀取交易並等待；成功時保存 MDR | LOAD_WB |
| **LOAD_WB** | 擷取並擴展 MDR 的資料，寫回 rd；PC←InstrPC＋4 | FETCH |
| **STORE_WAIT** | 發出一次寫入交易並等待；成功時 PC←InstrPC＋4 | FETCH |
| **BR_EXEC** | 計算分支目標存入 ALUOut，同時保存 BranchTaken | BR_COMMIT |
| **BR_COMMIT** | 成立時檢查目標對齊並跳躍；不成立則 PC←InstrPC＋4 | FETCH |
| **JUMP_EXEC** | 計算 JAL／JALR 目標，保存 ALUOut；JALR 先清 bit 0 | JUMP_COMMIT |
| **JUMP_COMMIT** | 檢查目標對齊；成功時 rd←InstrPC＋4，PC←ALUOut | FETCH |
| **FENCE_COMMIT** | 確認沒有未完成的記憶體交易，再令 PC←InstrPC＋4 | FETCH |
| **HALTED** | 保持停止狀態與錯誤資訊，不啟動新交易 | 等待 Reset |

共 15 個狀態；一般二進位編碼需要 4-bit。等待狀態可以停留多拍。

**8．各類指令的狀態路徑**

正常指令先經過：

```
FETCH → DECODE
```

再依指令類別分流。

| 指令類別 | DECODE 後的路徑 |
| --- | --- |
| ADD／SUB／AND／OR／XOR／SLT／SLTU／Shift | ALU_EXEC → ALU_WB → FETCH |
| ADDI 等立即數運算 | ALU_EXEC → ALU_WB → FETCH |
| LUI／AUIPC | ALU_EXEC → ALU_WB → FETCH |
| Load | ADDR_EXEC → MEM_CHECK → LOAD_WAIT → LOAD_WB → FETCH |
| Store | ADDR_EXEC → MEM_CHECK → STORE_WAIT → FETCH |
| Branch | BR_EXEC → BR_COMMIT → FETCH |
| JAL／JALR | JUMP_EXEC → JUMP_COMMIT → FETCH |
| FENCE | FENCE_COMMIT → FETCH |
| ECALL／EBREAK／非法指令 | 保存停止原因 → HALTED |

---

**9．等待與錯誤轉移**

| 目前狀態 | 條件 | 行為 |
| --- | --- | --- |
| FETCH | 回應尚未完成 | 留在 FETCH；不重複發出已接受的交易 |
| FETCH | 取指成功 | 保存 IR、InstrPC，進 DECODE |
| FETCH | 取指失敗 | 保存原因與取指地址，進 HALTED |
| DECODE | 非法指令、ECALL、EBREAK | 保存對應原因與 InstrPC，進 HALTED |
| MEM_CHECK | 地址未對齊 | 保存錯誤，進 HALTED；**不發出資料存取** |
| LOAD_WAIT／STORE_WAIT | 回應尚未完成 | 留在原狀態；不重複交易 |
| LOAD_WAIT／STORE_WAIT | 回報存取錯誤 | 保存錯誤，進 HALTED；不正常寫回、不前進 PC |
| BR_COMMIT | Branch 不成立 | 不檢查未採用目標的對齊；PC←InstrPC＋4 |
| BR_COMMIT | Branch 成立但目標未對齊 | 保存錯誤，進 HALTED |
| JUMP_COMMIT | 目標未對齊 | 進 HALTED；**不寫 rd，也不更新 PC** |
| HALTED | 沒有 Reset | 保持停止 |
| 任意狀態 | Reset 在上升緣有效 | 回到 FETCH，PC 與內部狀態初始化 |

取指失敗時，IR／InstrPC 可能仍保存上一條指令，因此 `fault_pc` 使用**這次取指的 PC**。

**12．各狀態的暫存器更新與寫回**

| 狀態 | 何時允許更新 | 啟用的寫入訊號 | 寫入內容／選擇 |
| --- | --- | --- | --- |
| FETCH | 取指回應成功時 | `ir_we`、`instr_pc_we` | IR←指令；InstrPC←本次取指位址 |
| DECODE | 指令合法且需要繼續執行時 | `ab_we` | A←rs1 資料；B←rs2 資料 |
| ALU_EXEC | 正常執行 | `aluout_we` | ALUOut←ALU 結果 |
| ALU_WB | 正常執行 | `reg_we`、`pc_we` | `wb_sel=ALUOut`；`pc_sel=順序` |
| ADDR_EXEC | 正常執行 | `aluout_we` | ALUOut←有效位址 |
| MEM_CHECK | 無一般資料更新 | 無 | 只檢查地址並選擇下一狀態 |
| LOAD_WAIT | 讀取回應成功時 | `mdr_we` | MDR←讀回的原始資料 |
| LOAD_WB | 正常執行 | `reg_we`、`pc_we` | `wb_sel=Load結果`；`pc_sel=順序` |
| STORE_WAIT | 寫入回應成功時 | `pc_we` | `pc_sel=順序`；不寫 rd |
| BR_EXEC | 正常執行 | `aluout_we`、`branch_taken_we` | 保存目標及比較結果 |
| BR_COMMIT | 不跳躍，或跳躍且目標對齊 | `pc_we` | 不成立選順序；成立選 ALUOut |
| JUMP_EXEC | 正常執行 | `aluout_we` | 保存處理後的跳躍目標 |
| JUMP_COMMIT | 目標對齊時 | `reg_we`、`pc_we` | `wb_sel=InstrPC＋4`；`pc_sel=ALUOut` |
| FENCE_COMMIT | 沒有未完成交易時 | `pc_we` | `pc_sel=順序` |
| HALTED | 無正常更新 | 無 | 保持 PC、資料及停止資訊 |

`pc_sel=順序` 表示選擇 `InstrPC＋4`。

**13．記憶體交易意圖**

交易意圖由 FSM 產生，再交給介面控制邏輯配合 `mem_pending` 產生外部握手訊號。

| 狀態 | 交易意圖 | 讀／寫 | 地址與資料 |
| --- | --- | --- | --- |
| FETCH | `ifetch_active=1` | 讀取指令 | 地址＝PC |
| LOAD_WAIT | `daccess_active=1` | `dmem_req_write=0` | 有效位址＝ALUOut；`dmem_req_wstrb=0` |
| STORE_WAIT | `daccess_active=1` | `dmem_req_write=1` | 有效位址＝ALUOut；資料來自 B 的對齊處理結果 |
| 其他狀態 | 兩者皆為 0 | 不啟動交易 | — |

資料介面實際送出的地址會依第 16 節對齊。不能將整段等待期間視為不斷啟動新交易。

**14．記憶體介面**

以下 `req_*`／`rsp_*` 是共用名稱，實際分為 `imem_*` 與 `dmem_*`。

| 訊號 | 方向（相對 CPU） | 意義 |
| --- | --- | --- |
| `req_valid` | 輸出 | CPU 提出有效請求 |
| `req_ready` | 輸入 | 記憶體介面可以接受請求 |
| `req_addr[31:0]` | 輸出 | 本次交易地址 |
| `req_write` | 輸出 | 0＝讀；1＝寫；指令介面固定為 0 |
| `req_wdata[31:0]` | 輸出 | 寫入資料 |
| `req_wstrb[3:0]` | 輸出 | 每個 bit 控制一個 byte；讀取時為 0 |
| `rsp_valid` | 輸入 | 回應有效 |
| `rsp_ready` | 輸出 | CPU 可以接受回應 |
| `rsp_rdata[31:0]` | 輸入 | 讀回的資料 |
| `rsp_error` | 輸入 | 1＝本次存取失敗 |

在 clock 上升緣：

```
req_valid && req_ready → 請求被接受
rsp_valid && rsp_ready → 回應被接受，交易完成
```

請求接受不代表存取成功。Store 也要等到成功回應，才能前進 PC。

**15．pending 與交易規則**

| 目前情況 | CPU 行為 | 記憶體介面行為 |
| --- | --- | --- |
| 進入 FETCH／LOAD_WAIT／STORE_WAIT，pending＝0 | 提出請求，`req_valid=1` | 用 `req_ready` 表示是否可接受 |
| `req_valid=1`，但 `req_ready=0` | 保持 valid、地址及所有請求欄位不變 | 可以繼續等待 |
| 請求握手成功 | 上升緣令 pending←1 | 接收一次請求，不得重複執行 |
| pending＝1 | `req_valid=0`，等待回應；對應介面 `rsp_ready=1` | 完成後提供回應 |
| 回應尚未被接受 | 保持等待 | 保持 `rsp_valid`、資料與錯誤旗標穩定 |
| 回應握手成功 | pending←0；依成功或失敗處理 | 本筆交易結束 |

第一版不接受請求與其回應在同一個上升緣完成，最早在下一個上升緣接受回應。

```
T0：請求未被接受，保持請求
T1：請求握手成功，pending ← 1
T2：等待回應，不重新送請求
T3：回應握手成功，pending ← 0
```

**16．地址、byte lane 與 Load／Store**

完整有效位址保存在 ALUOut。通過對齊檢查後，資料介面使用：

```
req_addr = ALUOut & 0xFFFFFFFC
offset   = ALUOut[1:0]
```

讀取回傳從對齊地址開始的完整 32-bit word。

| 存取 | 對齊要求 | 寫入遮罩／讀取方式 |
| --- | --- | --- |
| SB | 任意地址 | `wstrb = 0001 << offset` |
| SH | offset＝0 或 2 | `wstrb = 0011 << offset` |
| SW | offset＝0 | `wstrb = 1111` |
| LB／LBU | 任意地址 | 選出 offset 指定的 byte |
| LH／LHU | offset＝0 或 2 | 選出對應 halfword |
| LW | offset＝0 | 使用完整 word |

Store：

```
req_wdata = B << (8 × offset)
```

只更新 `wstrb` 指定的 byte，其餘保持原值。

Load：

```
MDR 右移 8 × offset
    ↓
取低 8／16／32-bit
    ↓
LB／LH：符號擴展
LBU／LHU：零擴展
LW：完整 32-bit
```

例如把 `0xAA` 寫到 `0x10000001`：

```
req_addr  = 0x10000000
req_wdata = 0x0000AA00
req_wstrb = 0010
```

- *MMIO 補充事項：**初版規劃只允許對齊的 word 存取。CPU／介面必須在對齊地址送出前保留足夠資訊，才能拒絕窄幅 MMIO 讀取；目前介面表沒有外傳 `mem_size`，這項檢查的責任位置留到 Day 6 明確指定。

**17．記憶體回應對 FSM 的影響**

| 狀態 | 成功回應 | 錯誤回應 |
| --- | --- | --- |
| FETCH | IR←指令；InstrPC←PC；進 DECODE | 不更新 IR／InstrPC；記錄取指錯誤，進 HALTED |
| LOAD_WAIT | MDR←讀回資料；進 LOAD_WB | 不更新 MDR／rd／PC；記錄讀取錯誤，進 HALTED |
| STORE_WAIT | PC←InstrPC＋4；進 FETCH | 不前進 PC；記錄寫入錯誤，進 HALTED |

`rsp_error` 只在回應握手成功時採樣。

第一版自製 RAM／MMIO 的契約是：**回報失敗的 Store 不得修改目標。** 因此能事前判斷的地址、遮罩等錯誤，要在寫入副作用發生前處理。

**18．錯誤與更新優先規則**

| 情況 | 必須採取的動作 |
| --- | --- |
| Reset 有效 | 優先初始化核心，回到 FETCH |
| 記憶體回應完成且帶錯誤 | 走錯誤路徑，不視為成功；不寫 IR／MDR，不正常前進 PC |
| MEM_CHECK 發現未對齊 | 不進入資料交易，保存錯誤並停止 |
| BR_COMMIT：分支成立但目標未對齊 | 不更新 PC，保存錯誤並停止 |
| JUMP_COMMIT：目標未對齊 | `reg_we=0`、`pc_we=0`，保存錯誤並停止 |
| 偵測到停止事件 | `halt_info_we=1`，保存原因與相關位址，State←HALTED |
| 已處於 HALTED | `halt_info_we=0`，保持第一次保存的資訊 |

**19．停止資訊與原因編碼**

| 項目 | 定義 |
| --- | --- |
| `halted` | `State == HALTED` |
| `halt_cause[3:0]` | 停止原因 |
| `fault_pc[31:0]` | 發生事件的指令位址；取指失敗時使用本次取指 PC |
| `fault_addr[31:0]` | 相關存取／跳躍位址，沒有相關地址時為 0 |
| `halt_info_we` | 只在首次進入 HALTED 時保存資訊 |

以下是**本專案自訂編號，不是標準 RISC-V `mcause` 編碼**。

| 編號 | 原因 | `fault_addr` |
| --- | --- | --- |
| 0 | 無停止事件 | 0 |
| 1 | 非法指令 | 0 |
| 2 | 指令目標未對齊 | 目標地址 |
| 3 | 取指存取失敗 | 取指地址 |
| 4 | Load 未對齊 | 原始有效位址 |
| 5 | Store 未對齊 | 原始有效位址 |
| 6 | Load 存取失敗 | 原始有效位址 |
| 7 | Store 存取失敗 | 原始有效位址 |
| 8 | ECALL | 0 |
| 9 | EBREAK | 0 |

**20．Reset 與未完成交易**

第一版採 **CPU、記憶體介面及周邊控制邏輯共同 Reset**。

| 情況 | 規定 |
| --- | --- |
| Reset 有效 | 不提出請求、不接受回應；在有效上升緣清除 pending 與停止資訊，PC←0，State←FETCH，初始化核心暫存器 |
| 有舊交易尚未完成 | 介面清除舊交易狀態，Reset 解除後不得送回舊回應 |
| 寫入已經發生 | Reset 不保證回復已寫入的 RAM 資料，也不能撤回已送出的 UART 資料 |
| 記憶體內容 | Reset 不自動清空整個程式／資料記憶體 |
| Reset 解除 | 從 PC＝0 重新取指 |

不能只重置 CPU，卻讓介面把舊回應當成新交易的回應。若日後需要獨立重置 CPU，必須另外設計排空或隔離機制。

**21．模組分工與介面**

表中的 `[32]` 表示 32-bit；控制選擇訊號的編碼統一放在 `fault_v_pkg.sv`。

| 模組 | 主要輸入 | 主要輸出 | 負責內容 |
| --- | --- | --- | --- |
| `cpu_top` | `clk`、`rst`、指令／資料介面回應 | 指令／資料請求、停止資訊 | 連接核心各模組 |
| `decoder` | `instruction[32]` | `rs1[5]`、`rs2[5]`、`rd[5]`、指令類別、ALU 操作、立即數格式、分支種類、存取寬度、unsigned、illegal | 解碼並檢查支援的指令編碼 |
| `imm_gen` | `instruction[32]`、`imm_sel` | `imm[32]` | I／S／B／U／J 立即數重組與擴展 |
| `regfile` | `clk`、`rst`、兩個讀取地址、`rd_we`、寫入地址、`rd_data[32]` | `rs1_data[32]`、`rs2_data[32]` | 32×32-bit、兩讀一寫、x0 固定零 |
| `alu` | `a[32]`、`b[32]`、`alu_op` | `result[32]` | 加減、邏輯、移位、比較 |
| `branch_cmp` | `a[32]`、`b[32]`、`branch_cond` | `taken` | BEQ／BNE／BLT／BGE／BLTU／BGEU 的條件判斷 |
| `datapath` | 控制訊號、立即數、RegFile 資料、記憶體读回資料 | PC、IR、InstrPC、ALUOut、寫回資料與檢查所需資訊 | 保存資料路徑暫存器，包含 MUX、JALR 目標處理及 PC＋4 |
| `load_store_unit` | ALUOut、B、MDR、`mem_size`、`load_unsigned` | 對齊地址、寫入資料、byte enable、Load 結果、未對齊與 MMIO 寬度違規旗標 | 資料整理與發出交易前檢查 |
| `controller` | 解碼結果、BranchTaken、檢查旗標、交易完成／錯誤、pending | State、寫入使能、選擇訊號、交易意圖、停止事件 | 15 狀態 FSM 與控制 |
| `mem_if` | 交易意圖、請求內容、外部 ready／response | 外部請求、內部完成／錯誤／資料、`mem_pending` | 單筆未完成交易與握手控制 |
| `halt_regs` | `clk`、`rst`、`halt_info_we`、原因與位址 | `halt_cause[4]`、`fault_pc[32]`、`fault_addr[32]` | 保存首次停止資訊 |

暫存器的管理責任：

| 模組 | 負責保存 |
| --- | --- |
| `datapath` | PC、IR、InstrPC、A、B、ALUOut、MDR、BranchTaken |
| `regfile` | x0～x31 的暫存器儲存 |
| `controller` | State |
| `mem_if` | mem_pending |
| `halt_regs` | halt_cause、fault_pc、fault_addr |

**同一個暫存器只有一個模組負責更新。** `halted` 直接由 `State == HALTED` 產生。

**22．控制欄位寬度與共用編碼**

| 項目 | 寬度 | 選項／定義 |
| --- | --- | --- |
| State | 4-bit | 15 個 FSM 狀態 |
| `instr_class` | 4-bit | REG_ALU、IMM_ALU、LUI、AUIPC、LOAD、STORE、BRANCH、JAL、JALR、FENCE、ECALL、EBREAK、INVALID |
| `alu_op` | 4-bit | ADD、SUB、AND、OR、XOR、SLL、SRL、SRA、SLT、SLTU |
| `imm_sel` | 3-bit | NONE、I、S、B、U、J |
| `alu_src_a` | 2-bit | A／InstrPC／0 |
| `alu_src_b` | 1-bit | B／Imm |
| `wb_sel` | 2-bit | ALUOut／Load 結果／InstrPC＋4 |
| `pc_sel` | 1-bit | InstrPC＋4／ALUOut |
| `branch_cond` | 3-bit | EQ、NE、LT、GE、LTU、GEU |
| `mem_size` | 2-bit | BYTE、HALF、WORD；剩餘編碼非法 |
| 暫存器地址 | 5-bit | rs1、rs2、rd |
| 寫入使能與布林旗標 | 1-bit | 如 `reg_we`、`pc_we`、`load_unsigned`、`jalr_target_sel` |

實際數值由共用 enum 定義。各模組使用編碼名稱，避免各自硬寫不同數字。

State 的 4-bit 是 RTL 宣告方式，合成工具仍可能依設定重新編碼。

**23．CPU 外部記憶體介面定稿**

| 訊號 | 寬度 | 方向（相對 CPU） | 意義 |
| --- | --- | --- | --- |
| `imem_req_valid` | 1 | 輸出 | 取指請求有效 |
| `imem_req_ready` | 1 | 輸入 | 取指請求可被接受 |
| `imem_req_addr` | 32 | 輸出 | 取指地址 |
| `imem_rsp_valid` | 1 | 輸入 | 取指回應有效 |
| `imem_rsp_ready` | 1 | 輸出 | CPU 可接受取指回應 |
| `imem_rsp_rdata` | 32 | 輸入 | 讀回的指令 |
| `imem_rsp_error` | 1 | 輸入 | 取指失敗 |
| `dmem_req_valid` | 1 | 輸出 | 資料請求有效 |
| `dmem_req_ready` | 1 | 輸入 | 資料請求可被接受 |
| `dmem_req_addr` | 32 | 輸出 | 4-byte 對齊的交易地址 |
| `dmem_req_write` | 1 | 輸出 | 0＝讀；1＝寫 |
| `dmem_req_wdata` | 32 | 輸出 | 對齊處理後的寫入資料 |
| `dmem_req_wstrb` | 4 | 輸出 | 寫入 byte enable |
| `dmem_rsp_valid` | 1 | 輸入 | 資料回應有效 |
| `dmem_rsp_ready` | 1 | 輸出 | CPU 可接受資料回應 |
| `dmem_rsp_rdata` | 32 | 輸入 | 讀回的完整 word |
| `dmem_rsp_error` | 1 | 輸入 | 資料存取失敗 |

指令介面固定為讀取，因此不外傳 `imem_req_write`、`imem_req_wdata`、`imem_req_wstrb`。

內部完成事件：

```
txn_done = 對應介面的 rsp_valid && rsp_ready
txn_ok   = txn_done && !rsp_error
txn_fail = txn_done &&  rsp_error
```

只有 `txn_ok` 才能觸發正常的 IR、MDR 或 PC 更新。

**24．記憶體介面與檢查責任**

| 問題 | 微架構 v0.1 決定 |
| --- | --- |
| 誰檢查 Load／Store 對齊？ | `load_store_unit` 產生旗標，controller 在 MEM_CHECK 處理；失敗不發出交易 |
| MMIO 預留區 | `0x20000000～0x20000FFF` |
| MMIO 存取寬度 | 初版只允許對齊的 LW／SW |
| 誰拒絕窄幅 MMIO？ | CPU 在 MEM_CHECK、發出交易前檢查 |
| 窄幅 MMIO 如何回報？ | 對齊檢查優先；若對齊但寬度不支援，使用 Load／Store 存取失敗原因碼 6／7 |
| 哪些 MMIO 地址有效？ | 外部周邊解碼器判斷；預留區不代表每個地址都有周邊 |
| 未配置的地址 | 外部介面回傳存取錯誤 |
| 外部是否需要 `mem_size`？ | 此版不需要；CPU 檢查寬度，外部以 word 地址與 `wstrb` 執行 |
| 原始有效位址是否保留？ | ALUOut 保留原始地址；只將外送地址對齊 |
| 誰阻止重複請求？ | mem_if；請求接受後 pending＝1，關閉 req_valid |
| 回應由誰接受？ | 只接受目前 pending 交易所屬介面的回應；另一介面 rsp_ready＝0 |
| 同拍請求與回應 | 不在同一上升緣接受；提早送出的 rsp_valid 必須保持到接受 |
| 記憶體不回應 | v0.1 不設硬體 timeout，持續等待；testbench 用超時機制發現問題 |
| Reset 後舊回應 | 由共同 Reset 清除，禁止混入新交易 |

`0x20000000` 仍為程式狀態暫存器；UART／GPIO 的詳細地址於周邊設計時分配。

此表完成第 16 節留下的 **MMIO 寬度檢查責任**。

**25．各類指令的完整路徑檢查**

共同起點為：

```
FETCH → DECODE
```

| 指令類別 | DECODE 後的路徑 | 關鍵檢查 |
| --- | --- | --- |
| R-type 運算 | ALU_EXEC → ALU_WB → FETCH | ALU 使用 A、B；依操作區分 signed／unsigned |
| 立即數運算 | ALU_EXEC → ALU_WB → FETCH | ALU 使用 A、Imm；立即數移位使用低 5-bit |
| LUI | ALU_EXEC → ALU_WB → FETCH | 左輸入選 0，右輸入選 U-type Imm |
| AUIPC | ALU_EXEC → ALU_WB → FETCH | 使用 InstrPC 計算 |
| Load | ADDR_EXEC → MEM_CHECK → LOAD_WAIT → LOAD_WB → FETCH | 先檢查後請求；成功保存 MDR，下一狀態才擷取並寫回 |
| Store | ADDR_EXEC → MEM_CHECK → STORE_WAIT → FETCH | B 保持穩定；只接受一次交易；成功回應才前進 PC |
| Branch | BR_EXEC → BR_COMMIT → FETCH | 目標與判斷分別保存；不成立時不檢查未採用目標 |
| JAL | JUMP_EXEC → JUMP_COMMIT → FETCH | 對齊成功後，寫回 InstrPC＋4 並更新 PC |
| JALR | JUMP_EXEC → JUMP_COMMIT → FETCH | 使用已保存的 A；清 bit 0 後再檢查 4-byte 對齊 |
| FENCE | FENCE_COMMIT → FETCH | 無未完成交易才前進 |
| ECALL／EBREAK | HALTED | 保存不同停止原因，不前進 PC |
| 非法指令 | HALTED | 不進入正常執行路徑 |

共同補充規則：

- `rd=x0` 時丟棄寫回，**不取消其他行為**；例如 `lw x0,...` 仍須執行存取及錯誤檢查。
- JALR 即使 `rd=rs1`，仍使用 Decode 已保存到 A 的舊來源值計算目標。
- JAL／JALR 跳到對齊但無效的地址，先完成跳躍；下一次 FETCH 回報存取失敗，已完成的返回位址寫回不撤銷。
- 整數加法與地址計算保留低 32-bit，不另增加算術溢位停止。
- 前一條指令完成並回到 FETCH 後，才開始下一條，不重疊執行。

**26．錯誤與 Reset 最終規則**

| 情況 | 行為 |
| --- | --- |
| Reset | 最高優先；清除核心暫存器、pending、停止資訊；State←FETCH、PC←0 |
| Load／Store 同時有未對齊及區域問題 | MEM_CHECK 先回報未對齊，不發出交易 |
| 記憶體回應帶錯誤 | 僅於回應握手完成時採樣，不做該指令的正常寫回及 PC 前進 |
| 取指錯誤 | `fault_pc`、`fault_addr` 使用本次取指 PC |
| 資料存取錯誤 | `fault_pc=InstrPC`；`fault_addr=ALUOut` 的原始有效位址 |
| 跳躍未對齊 | `fault_pc=InstrPC`；`fault_addr=ALUOut` 的跳躍目標 |
| 非法指令／ECALL／EBREAK | `fault_pc=InstrPC`；`fault_addr=0` |
| HALTED | 不啟動交易、不正常寫回；保存第一次停止資訊直到 Reset |
| Reset 前已完成的 RAM 寫入／UART 輸出 | 不保證撤銷；共同 Reset 保證不送回過期回應 |

停止原因編碼沿用第 19 節的 **0～9**，不改動。
